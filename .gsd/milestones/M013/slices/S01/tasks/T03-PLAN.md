# T03: Support remote spec URLs on Gradle delivery surfaces and prove sanitized retained artifacts

**Slice:** S01 — Supported Remote Spec Inputs With Sanitized Provenance
**Milestone:** M013

## Description

The slice closes only when the real Gradle path and retained proof artifacts show the same narrow remote-support contract as the CLI.

## Steps

1. Update `yanote-gradle-plugin` tasks so supported remote `http(s)` spec URLs bypass local `project.file(...)` existence checks, keep local paths strict, and write sanitized `yanote-check-command.args` / `yanote-report-command.args` surfaces instead of raw remote URLs.
2. Parameterize the CI helper script in `scripts/ci/run-yanote-gradle-check.sh` for local vs remote spec sources and add a focused Gradle contract test that pins remote acceptance plus local-path fail-closed behavior.
3. Add `bash scripts/ci/verify-m013-s01-remote-spec.sh` to serve a fixture spec over localhost, run Yanote from local file, local directory, and remote URL inputs, exercise the Gradle entrypoint against the fixture URL, and assert a retained proof bundle with sanitized provenance only.

## Must-Haves

- [ ] Gradle keeps local path validation strict and widens only the supported remote-URL subset.
- [ ] Persisted command-argument files show sanitized source provenance rather than raw remote URLs.
- [ ] The proof bundle demonstrates remote URL success alongside the unchanged local file/directory baseline.
