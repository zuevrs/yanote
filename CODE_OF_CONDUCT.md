# Кодекс поведения / Code of Conduct

Yanote — maintainer-led open-source проект. Мы хотим, чтобы обсуждения, issues, PR и review оставались профессиональными, уважительными и предметными.

## Наши ожидания

Мы ожидаем от участников проекта:

- уважительного и ясного общения;
- критики идей и реализации, а не людей;
- аккуратного обращения с чужим временем: минимальные воспроизведения, точные команды, релевантные артефакты;
- честного описания ограничений, рисков и неопределённостей;
- соблюдения публичных границ проекта вместо давления на мейнтейнера с требованием расширить scope «по умолчанию».

## Неприемлемое поведение

В проекте не приветствуются:

- персональные оскорбления, травля, угрозы или дискриминация;
- навязчивое, агрессивное или манипулятивное общение;
- публикация приватной информации без согласия;
- спам, флуд или заведомо нерелевантные issue/PR;
- публикация секретов, приватных ключей, токенов, неотредактированных чувствительных payload/body/header значений.

## Правоприменение / Enforcement

Мейнтейнер может:

- попросить скорректировать тон или scope обсуждения;
- закрыть issue/PR, который не соответствует этому кодексу или публичным границам проекта;
- ограничить дальнейшее взаимодействие, если нарушение повторяется.

## Куда писать

- Для обычных bug/integration/docs вопросов используйте публичные issue templates.
- Для нераскрытых уязвимостей используйте только [SECURITY.md](SECURITY.md).
- Для сообщений о нарушении этого кодекса пишите на `zzuevrs@gmail.com` и приложите минимально нужный контекст.

Этот кодекс сознательно остаётся коротким: Yanote — небольшой проект с явным single-maintainer ownership, без имитации большой governance-структуры.
